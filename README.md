# Каталог книг — аттестация, раздел 1

Flutter-приложение с Firebase Authentication, Cloud Firestore и Cubit.

## Запуск и проверка

```sh
flutter pub get
flutter run
flutter analyze
flutter test
```

Для Web можно использовать `flutter run -d chrome` или
`flutter run -d web-server --web-port=8092`.
Firebase настроен для Android и Web, проект `catalog-139d6`.
Для регистрации в учебном приложении используйте тестовые адреса вида
`test1@test.com`, `test2@test.com`. Пароль — не менее 6 символов.
Авторизация сохраняется Firebase между запусками.

## Что реализовано

- Вход, регистрация, выход и понятные сообщения об ошибках с кодом Firebase.
- Каталог из коллекции `books`: загрузка, ошибка с кнопкой «Обновить», пустое состояние.
- Цветная обложка, название, автор, год, категория и лайк в карточке.
- Экран деталей с полным названием, описанием, остальными полями и общим лайком.
- Добавление в диалоге: обязательное название и необязательное описание.
- Избранное сохраняется в `users/{uid}/favorites/{bookId}`, отдельно для каждого аккаунта.
- Старые документы без `description` читаются без миграции.
- **Дополнительная опция № 6: обновление каталога в реальном времени.**
  Изменения в Firebase Console появляются через `snapshots()` без обновления экрана.

## Где что находится

- `lib/main.dart` — инициализация Firebase, наблюдение за сессией,
  `RepositoryProvider` и `BlocProvider`. При смене аккаунта создаются новый Cubit
  и новый стек навигации: детали прошлого аккаунта не остаются поверх входа.
- `lib/data/book_api.dart` — репозиторий: вся работа с Firebase, преобразование ошибок.
  Загрузка сначала обращается к серверу с таймаутом, затем слушает изменения.
  Поэтому «Обновить» без интернета показывает ошибку вместо пустого кэша.
- `lib/domain/entities/book.dart` — модель, `fromFirestore` с `doc.id`, `toJson`.
- `lib/domain/catalog_cubit.dart` — состояния загрузки, данных и ошибки;
  подписки на книги и избранное, лайк, фильтр и добавление.
- `lib/ui/screens/` — вход, каталог, детали, диалог добавления.
  Каталог и детали строятся через `BlocBuilder`. `setState` используется только
  для состояния полей и ошибок формы; виджеты к Firebase напрямую не обращаются.
- `firestore.rules` — книги доступны вошедшим пользователям, избранное — только владельцу.
  Публикация: `firebase deploy --only firestore:rules --project catalog-139d6`.

После `add` список не изменяется вручную: новый документ приходит в поток,
Cubit публикует новое состояние, `BlocBuilder` обновляет экран.
Лайки в списке и деталях читают одно состояние Cubit.

## План собственного видео (до 5 минут, с голосом)

1. **0:00–0:20** — вход или регистрация; после входа — каталог.
2. **0:20–0:40** — прокрутка списка из 8+ книг, лайк и «Только избранные»;
   показать пустое избранное второго тестового аккаунта.
3. **0:40–1:10** — диалог добавления: проверить пустое название,
   добавить книгу с описанием, открыть детали и вернуться назад.
4. **1:10–1:35** — отключить интернет на тестовом устройстве, потянуть список вниз для обновления,
   дождаться сообщения об ошибке (до 15 секунд). Восстановить интернет и нажать «Обновить» на экране ошибки.
5. **1:35–2:00** — выход, повторный вход: избранное сохранилось;
   перезапустить приложение: сессия и добавленная книга сохранились.
6. **2:00–2:20** — назвать опцию № 6, изменить название книги в Firebase Console
   и показать обновление приложения без ручной перезагрузки.
7. **2:20–4:40** — объяснить своими словами цепочку
   модель → репозиторий → Cubit → BlocBuilder. Показать методы загрузки,
   лайка, фильтра и добавления, а также привязку избранного к uid.

До записи заранее откройте перечисленные файлы и один раз пройдите сценарий.
Для сдачи нужны ваше видео с объяснением кода, открытый PR `project` в `main`
и строка: «Опция № 6 — обновление каталога в реальном времени».
Не мерджите финальный PR самостоятельно.
